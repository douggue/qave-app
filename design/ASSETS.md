# Lokal: assets plan

Custom "fun emoji" replace the phone's built-in emoji everywhere they carry meaning:
map pins, reports, avatars, celebrations, badges. Plain utility icons (back, share,
settings) come from a standard icon set so the custom set stays focused.

## Why custom

- Built-in emoji look different on iPhone, Android and the web. Custom ones look the same everywhere.
- Apple's and Samsung's emoji artwork can't be used as app graphics. Custom art (or a properly licensed set) can.
- The emoji are the personality of the app. They should feel like ours.

## Style guide

- **Look:** glossy "sticker" style with soft 3D shading, made to pop on the night map.
- **Rim:** a thin white rim (about 4% of the size) so every emoji reads on dark and light maps.
- **Light:** always from the top left. One soft shadow at the bottom right.
- **Shapes:** chunky and simple. Each must read clearly at 24 px.
- **Color:** saturated food colors. Each food also gets a **glow color** used for its pin glow (see manifest).
- **No text** inside emoji (so nothing needs translating).
- **Consistency check:** every new emoji is reviewed next to the taco, the truck and the fire before it's approved.

## Technical specs

| Item | Master | Export | Notes |
|---|---|---|---|
| Static emoji | Vector (Figma or SVG), 256 × 256 artboard, 16 px safe margin | PNG at 72, 144, 216 px (1x/2x/3x of 72 pt) | Transparent background. Aim for under 12 KB each at 3x. |
| Map pin images | Same masters | PNG at 168 px (56 pt @3x) | Loaded into Mapbox as symbol images. |
| Animations | After Effects or a Lottie editor | Lottie JSON | Under 100 KB each, 60 fps, no embedded images. |
| UI icons | Standard set (Phosphor or Lucide) | SVG via react-native-svg | Not custom. |
| App icon | 1024 × 1024 | Generated by Expo from the master | No transparency on iOS. |

### manifest.json

One entry per emoji. The app reads this file, so swapping artwork never needs code changes.

```json
{
  "id": "food-taco",
  "label": "Tacos",
  "file": "food/food-taco.png",
  "glow": "#ff6f4f",
  "keywords": ["taco", "tacos", "al pastor", "birria", "mexican", "taqueria"]
}
```

`keywords` let the AI guide and the add-a-spot form match a spot or a question to the right emoji.

## Chosen approach

**AI-generated with ChatGPT**, then cleaned up and exported here (background removal, trim, rim check, sizes, manifest).

Base prompt (change only `[ITEM]`):

```
A single [ITEM] emoji icon in a glossy 3D sticker style.
Soft, rounded, chunky shapes, saturated appetizing colors, soft lighting
from the top left, a small soft shadow on the bottom right of the object,
and a thin white outline around the whole shape like a die-cut sticker.
Centered on a fully transparent background. Nothing else in the image:
no text, no letters, no logos, no border, no scenery.
Square 1:1 image, the object fills about 80% of the frame.
Part of a consistent, playful emoji set.
```

After the first approved image (the taco), keep working in the same chat and start each request with:
"Use the exact same style, lighting, outline and level of detail as the taco above. Now make: [ITEM]."

Notes: purely AI-generated images generally can't be copyrighted in the US, so a designer should refine the app icon or logo if it will be trademarked. Avoid anything resembling real brands or characters.

Ready-to-paste prompts for every sheet: [`EMOJI_PROMPTS.md`](EMOJI_PROMPTS.md).

## Where the art can come from

1. **Hire an illustrator** (for example through Dribbble, Behance or Upwork). Best result and fully ours. Ask for source files and full commercial rights in writing.
2. **AI-generated drafts, then cleaned up by a designer.** Faster and cheaper for exploring the style. Final files still need a human pass for consistency, and the rights to AI output should be checked before relying on it commercially.
3. **Open emoji sets as placeholders while building:**
   - Microsoft Fluent Emoji (3D style, close to our look), MIT license
   - Google Noto Emoji, Apache 2.0
   - Twemoji graphics, CC BY 4.0 (credit required)
   - OpenMoji, CC BY-SA 4.0 (share-alike terms; check before shipping)

   Confirm each license from its official source before shipping anything from it.

## Process

1. **Style test:** 6 emoji first: taco, burger, food-truck, amazing-fire, long-line-hourglass, avatar-fox. Review them on the real night and day map.
2. **Approve the style**, then produce the rest of P0 in batches by category (food first, since it's on every pin).
3. **Meanwhile the app is built with placeholders** (Fluent Emoji or the built-in emoji) through manifest.json. Swapping in final art is just replacing files.
4. **Delivery:** upload files to the `assets/emoji/` folder in this repo (from GitHub on a phone, or by sending them in chat), and the manifest gets updated.
5. **Check:** every emoji is reviewed at 24 px and 56 px on dark and light maps before it ships.
